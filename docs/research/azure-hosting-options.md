## 當時的 Azure 選型結論

若上 Azure，當時的選擇會是：

| 項目 | 選擇 | 理由 |
|---|---|---|
| 宿主 | App Service F1（Linux） | 真正 0 元、zip deploy 不用 Docker。代價是 20 分鐘閒置後卸載，冷啟動數秒到十幾秒 |
| Telegram 接收 | webhook，`secret_token` 驗證 | 免費層都會縮到零，long polling 無法常駐 |
| 圖片 | Telegram `file_id` 為主，Blob 當原圖備份（5 GB 約 0.15 美元/月） | `file_id` 重送沒有次數限制且永久有效 |
| Metadata | Azure Table Storage（約 0.001 美元/月）或 Cosmos DB 免費層（Table API） | SQLite 不能放在 App Service 的持久儲存上 |
| 後台登入 | App Service Easy Auth 綁 Microsoft 帳號 | 不自己寫登入頁 |
| 部署 | GitHub Actions zip deploy | |

次選是 Container Apps 縮到零（冷啟動 10 到 30 秒，要維護 image）。Functions 與 Static Web Apps 可用但程式模型不同，Functions 還要綁收費的 storage account。Azure SQL 免費層不建議：每月 10 萬 vCore 秒約 55 小時上線時間，webhook bot 加自動暫停延遲很容易用完。

與設備方案的完整比較表在 2026-10-25 的討論中，重點：兩邊都是 0 元；設備沒有冷啟動、不曝露，但可用性跟著設備；Azure 可從任何地方開後台、基礎設施不用自己維護，但有冷啟動與配額。

| **C.1 file_id reuse** | "Sending by file_id: If the file is already stored somewhere on the Telegram servers, you don't need to reupload it: each file object has a file_id field, simply pass this file_id as a parameter instead of uploading. ## Notable findings (things that change the design)

1. **Telegram will store and serve the images for free.** Re-sending by `file_id` has "no limits", file_ids are persistent, and a photo received from the user already has a `file_id`. The 1–5 GB of images therefore do not need to live in Azure; only a metadata index (keywords → `file_id`) is required. Caveat: `file_id` is per-bot, so keep `file_unique_id` and optionally a Blob/offline backup in case you ever move to a new bot. A Blob backup of 5 GB costs ≈ $0.15/month in East Asia (small, not free).
2. **Inline mode turns "search my memes" into `@bot keyword` in any chat**, via `InlineQueryResultCachedPhoto` + `photo_file_id`, ≤ 50 results, per-user caching (`is_personal`). Whether a text title shows on photo results is undocumented (generally it does not), so plan on captions rather than titles.
3. **Long polling removes the need for any public HTTPS endpoint** (the bot connects outbound), but it needs an always-running process, which none of the $0 Azure tiers provide (F1 has no Always On and a 60 CPU-min/day cap; Functions / Container Apps scale to zero). Webhook + an HTTPS host on port 443 is the natural fit for the free tiers; use `secret_token` to authenticate Telegram's POSTs.
4. **Truly $0 Azure hosts for a .NET 10 webhook endpoint**: Static Web Apps Free (managed Functions, `dotnet-isolated:10.0`, 45 s max per request, also hosts the admin UI), App Service F1 (Linux or Windows; 60 CPU-min/day, 165 MB/day egress, no Always On), Container Apps with scale-to-zero (10–30 s cold starts). Azure Functions Consumption / Flex are "≈ $0" because the mandatory storage account is billed (cents/month). Flex Consumption's free grant does exist (250k executions + 100k GB-s) but only for on-demand, never for always-ready instances.
5. **.NET 10 on Azure Functions Consumption is Windows-only**; Linux Consumption stops at .NET 9 and retires 30 Sep 2028. Use Flex Consumption (Linux, .NET 10) or Windows Consumption.
6. **SQLite is explicitly unsupported on App Service persistent storage** ("not possible to acquire exclusive locks" on the network share) and on Azure Files mounts. Use Cosmos DB free tier (1000 RU/s + 25 GB, any provisioned API incl. Table API, lifetime, 1 per subscription), Azure Table Storage (≈ $0.001/month for a few MB), Azure DocumentDB free tier (32 GB MongoDB, 60-day idle pause), or MongoDB Atlas Free (0.5 GB; GCP `asia-east1` Taiwan supports Free clusters) for metadata.
7. **Azure SQL free tier is risky for a webhook bot**: 100,000 vCore-s ≈ 55 online hours/month at the 0.5 vCore minimum; a 15–60 min auto-pause delay after every interaction can exhaust the quota mid-month; `AutoPause` (DB offline until next month) vs `BillOverUsage` (paid, irreversible) must be chosen at creation.
8. **The current Azure free-account page no longer advertises Blob 5 GB for 12 months** (unconfirmed whether removed); Blob/Table/Files have no always-free amount, so any Azure-side image copy is a small non-zero monthly charge. Internet egress is free for the first 100 GB/month, so serving images from Blob to Telegram adds no bandwidth cost at this scale.
9. **Telegram.Bot 22.10.3.3 already tracks Bot API 10.3** and ships both polling (`OnMessage` / `StartReceiving`) and webhook (`SetWebhook`, direct `Update` model binding in Minimal APIs) support; FastEndpoints 8.3 supports .NET 10 but its upcoming 9.0 drops .NET 8/9 – fine for a `net10.0` project, and Minimal APIs alone are adequate at this size.
